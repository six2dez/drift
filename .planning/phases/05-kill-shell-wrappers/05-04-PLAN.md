<objective>
Rewire `index.ts`'s MCP health path onto the direct-`node`-spawn keystone: one spec, three
orchestration sites, two config writers, and a win32-unreachable POSIX wrapper.

Purpose: this is the direct fix for the reported bug. Everything on the Claude and self-test paths
that needed `chmod`, a `#!/bin/bash` shebang or `.sh` execution goes away, and the Caido token and
`DRIFT_*` variables reach the server through the spawn `env` option and the config-JSON `env` field
instead of shell `export` lines.

Output: `index.ts` with `requireMcpServerSpec`, a spec-taking `validateCaidoAuth` and
`callMcpMethod`, both config writers on one projection, and the surviving POSIX wrapper reachable
only on darwin/linux.

**Honest ceiling, to be carried into the SUMMARY verbatim (D-08).** `index.ts` is not importable
under vitest, so nothing in this plan is covered by a test that executes it. The evidence is
plan 05-01's proof of the spec, the server and the spawn contract, plus this plan's static gates and
code review. That is bucket **N** row V-21 and it must not be reported as more than that.
