- `toMcpConfigDocument(spec: McpServerSpec): { mcpServers: { drift: { command: string; args: string[]; env: Record<string, string> } } }`
- `type McpCliRegistration = { kind: "Register"; wrapperPath: string } | { kind: "Skip"; reason: string }`
- `planMcpCliRegistration(input: { platform: Platform | undefined; cli: "gemini" | "codex"; wrapperPath: string | undefined }): McpCliRegistration`
- `formatSpawnDebugLine(input: { command: string; args: string[]; injectedKeys: string[] }): string`
- `findExpandableEnvKeys(driftVars: Record<string, string>): string[]`

**Two projections, deliberately distinct** (planner decision on RESEARCH § Open Questions #1):
`spec.env` is the parent-merged block and is what `spawn` receives; `spec.driftVars` is the ~9-key
dict and is what the config *documents* receive. `toMcpConfigDocument` reads `driftVars`, never
`env`. Rationale: the spawn path MUST merge (finding L-4), the config path must NOT — the external
CLI already gives its own child the parent environment, and writing the user's whole environment
into a `0o600` JSON file that D-10 makes token-bearing widens the blast radius of a support bundle
or a stray read for no functional gain. It also preserves Copilot's current config byte-shape
exactly (CMP-01).
