<objective>
Turn D-05's unverified `is process.env complete under LLRT?` risk into a reported, non-gating
measurement that a bug reporter can paste.

Purpose: after this phase every child receives a dict Drift builds from `process.env` as the Caido
runtime sees it, instead of inheriting a real shell environment through a `.sh` wrapper. Research
finding L-1 settles the LLRT half by source read — `process.env` is `std::env::vars()`, unfiltered —
but it does not settle whether the Caido HOST process has a usable PATH, which is a real negative
case (a macOS app launched from the Dock inherits four entries). D-05 says REPORT, not GATE, because
the fallback is real: the MCP server is spawned by absolute node path and spawns nothing itself.

Output: a fifth reported capability row and two integer metrics on `ProbeReport`, provable on the
Linux runner because the environment is an injected parameter.
</objective>

    - With `parentEnv: { PATH: "/usr/bin:/bin", HOME: "/x" }` and `normalizedPlatform: "linux"`, `parentEnvKeyCount` is `2` and `parentEnvPathEntryCount` is `2`.
    - With `parentEnv: { Path: "C:\\a;C:\\b;C:\\c" }` and `normalizedPlatform: "win32"`, `parentEnvPathEntryCount` is `3` — the key lookup is case-insensitive and the separator is the semicolon.
    - With `parentEnv: { PATH: "/usr/bin;/bin" }` and `normalizedPlatform: "linux"`, `parentEnvPathEntryCount` is `1` — the separator is chosen by platform, not by guessing from the content.
    - With `parentEnv: { HOME: "/x" }` (no PATH under any casing), the detail says the PATH variable is absent and `parentEnvPathEntryCount` renders the absent marker — a different string from the not-probed marker.
    - With a `parentEnv` supplied but `normalizedPlatform: undefined`, the key count is still reported and the PATH entry count renders not-probed, because the separator is unknowable.
    - Empty and whitespace-only PATH segments do not count: `"/usr/bin::/bin"` on linux is `2`, and `""` is `0`.
    - The row's `gating` field is `false`, and `report.ok` is unaffected by any parentEnv outcome including the absent one.
    - Neither the detail string nor either metric ever contains a key name other than the literal word for the PATH variable, and never contains any value.
  </behavior>
  <action>
Add a fifth entry to `PROBE_CAPABILITIES` with `name: "parentEnv"`, `label: "Parent process environment"`
and `gating: false`. Put the D-06 REPORT-versus-GATE reasoning in the entry's comment in the same
voice as the four existing entries: this REPORTS because the fallback is real — the MCP server is
spawned by an absolute node path and `mcp-server.mjs` spawns nothing itself, so a thin or missing

Phase 7's PRV-01. Gating on it would refuse to start on a runtime where the health check
demonstrably works.

Add the matching `CAPABILITY_PURPOSE` entry — the record is keyed by capability name specifically so
a new row cannot render a message with no what-for clause. Word it for a bug reporter: Drift builds
every child's environment from the parent block, so the size of that block and the number of PATH
entries are what a Windows or Dock-launched-macOS user needs to paste when a CLI is not found.

Add `describeParentEnvCapability` following the shape of the existing `describe*Capability` helpers.
It returns `ok: true` in every case — this row never fails — and its detail distinguishes three
states in words: not probed, PATH absent, and a measured entry count. Do not let the not-probed
detail contain the word used for the absent state; Phase 4's 04-03 established that a report written
to be pasted into a public bug report must never assert a measurement Drift did not make, and a test
in the next task enforces the distinction.

Add a private `countPathEntries(input: { parentEnv, platform })` helper. Resolve the PATH key by
scanning `Object.keys(parentEnv)` for the first key whose uppercase form equals the PATH variable
name — Windows environment keys are case-insensitive and a parent block spelling it `Path` must be
measured, not reported absent. Choose the separator from `platform`: the semicolon on `win32`, the
colon otherwise; return the not-probed state when the platform is unknown, because the separator is
then unknowable and a guess would produce a confidently wrong integer. Split, trim, drop empty
segments, and count.

Extend `buildProbeMetrics` to also emit `parentEnvKeyCount` and `parentEnvPathEntryCount`, and give
it the parentEnv and platform it needs. Extend `buildProbeReport`'s input type with an OPTIONAL

than introducing a second spelling.

Extend the module header's security paragraph with one sentence: this row emits integers and status
words only, so the standing rule that this module never enumerates the process environment holds
literally — counting is not enumerating, and neither the key names nor the values ever leave it.

Do not touch `index.ts`. Do not change any existing capability's `gating` value. Do not change
`formatProbeReportFields` — it already flattens `report.metrics` verbatim.
