Create `packages/backend/src/platform.ts` with a 4-6 line header comment stating that the module is
I/O-free by design, that `platform` is always an injected parameter, and that this is what lets the
Linux CI runner prove the Windows branches (cite SC-1 and the fact that the maintainer cannot test
native Windows locally).

**Import nothing.** This module has zero import statements. Do **not** import `os` — per **D-02**,
`os` is read in exactly one place and that place is `index.ts`. Do **not** import `path` either:
none of the nine exports below needs it (`getTempRoot` strips separators with explicit string logic
precisely *because* `path` is POSIX-shaped on the Linux test runner), and an unused
`import path from "path"` is a hard failure — tsconfig sets `noUnusedLocals` (TS6133) and
`pnpm lint` runs `eslint . --max-warnings 0` with `@typescript-eslint/no-unused-vars` at `error`, so
the import would break this task's own automated verification. Record the zero-import property in the header
comment: it is what makes SC-1's "no I/O" claim mechanically checkable with a single grep.

Export exactly these, in this order:

1. `export type Platform = "win32" | "darwin" | "linux";` — the narrow union deliberately, not
   `NodeJS.Platform`. Comment why: the narrow union is what forces the explicit normalisation check
   at the single `os.platform()` call site, which is where D-06's "unrecognised value gates" rule
   belongs.

2. `export function normalizePlatform(value: string | undefined): Platform | undefined` — an
   allow-list check against exactly `"win32"`, `"darwin"`, `"linux"`. Trim first; return `undefined`
   for `undefined`, empty, or anything outside the allow-list. Comment: Caido's LLRT hardcodes
   `PLATFORM` at compile time and its third arm is `std::env::consts::OS`, which can yield
   `"freebsd"`/`"android"`; an unrecognised value must **not** fall through to the POSIX arm because
   on Windows that is the reported bug reintroduced one layer up.

3. `export function getTempRoot(input: { platform: Platform; tmpdir: string }): string` — trims
   whitespace, then strips **trailing `/` and `\` characters** with explicit string logic (a loop or
   a regex), never `path.normalize`/`path.join`. Rationale to record in a comment: the unit tests run
   on Linux where `path` is POSIX, so `path.normalize` would not strip a trailing backslash from a
   Windows-shaped input; and LLRT's `os.tmpdir()` is `std::env::temp_dir()` → `GetTempPath2`, which
   is documented to return a path **ending in a backslash** while Node has stripped trailing
   separators since v2.0.0. Guard the strip so a root is never reduced to empty: stop while the
   remaining length is `<= 1`, and stop when the remaining string ends with `:` (so `"/"` stays
   `"/"` and `"C:\\"` stays `"C:\\"`).

4. `export function getSweepRoots(input: { platform: Platform; tmpdir: string }): string[]` — starts
   from `[getTempRoot(input)]`; when `input.platform !== "win32"` and the array does not already
   contain `"/tmp"`, pushes `"/tmp"`. Comment must state the security reason verbatim in substance:
   the shipped 0.1.0 wrote token-bearing `drift-mcp-*` directories to `/tmp`, and on macOS
   `os.tmpdir()` is `/var/folders/…`, so without this arm those directories would never be swept
   again after upgrade. This is the one Claude's-Discretion item with a security consequence and the
   agreed default is SHIP IT. This function is the entire CMP-02 proof.

5. `export function getWhichCommand(input: { platform: Platform }): { command: string; args: (cmd: string) => string[] }`
   — POSIX returns `{ command: "which", args: (cmd) => [cmd] }`; win32 returns
   `{ command: "where.exe", args: (cmd) => [cmd] }`. Use `"where.exe"`, not bare `"where"`:
   Phase 3's `P1-WHERE` measured `where.exe` on a real `windows-latest` host. Add a comment citing
   `.planning/phases/03-ci-spike-prove-llrt-basics-on-windows/03-FINDINGS.md` § `P1-WHERE` recording
   two facts Phase 6 will consume and Phase 4 deliberately does not implement: the measured
   invocation was by **absolute path** (`C:\Windows\System32\where.exe`), and the output was
   **2 CRLF-split lines**, so Phase 6 must split on `/\r?\n/`.

6. `export const WINDOWS_EXECUTABLE_EXTENSIONS = [".exe", ".cmd", ".bat"] as const;` — `.exe` first
   because Phase 6 SC-2 requires preferring `.exe` over `.cmd`. Comment that `.cmd`/`.bat` are the
   pair Phase 3's `P1-CMD` proved cannot be spawned directly (Node ≥ 18.20.2 throws `EINVAL`
   synchronously from the CVE-2024-27980 guard), which is why Phase 7 routes them through
   `cmd.exe /d /s /c`. Phase 4 only ships the list.

7. `export function getExecutableNames(input: { command: string; platform: Platform }): string[]` —
   on POSIX returns `[input.command]` unchanged. On win32: if `input.command` already ends
   (case-insensitively) with one of `WINDOWS_EXECUTABLE_EXTENSIONS`, return `[input.command]`;
   otherwise return `[command + ".exe", command + ".cmd", command + ".bat", command]` — the bare
   name last as a final fallback. De-duplicate with `[...new Set(...)]`. Trim the input; return `[]`
   for an empty command.

8. `export function getHomeDirCandidates(input: { platform: Platform; env: Record<string, string | undefined> }): string[]`
   — POSIX reads `input.env["HOME"]`; win32 reads `input.env["USERPROFILE"]`, `input.env["APPDATA"]`,
   `input.env["LOCALAPPDATA"]` in that order. Trim each, drop `undefined`/empty, de-duplicate with
   `[...new Set(...)]`. Per **D-03** this ships *which env var names to read* — the install-location
   candidate arrays built from them stay in Phase 6's `command-resolution.ts`.

9. `export function buildSpawnEnv(input: { parentEnv: Record<string, string | undefined>; driftVars: Record<string, string> }): Record<string, string>`
   — copies every string-valued entry of `input.parentEnv` into a fresh object, then spreads
   `input.driftVars` over it, returning `Record<string, string>` with no `undefined` values. Use the
   object-param form (not the positional form sketched in RESEARCH § *Code Example 4*) so the module
   stays internally consistent with D-01's convention and with `buildMcpRuntimeEnv`'s
   `input: {…}` → `Record<string, string>` contract at `index.ts:577`. It must **not** read module
   state — `parentEnv` is an input precisely so the SC-9 assertion is a pure unit test. Comment must
   cite `03-FINDINGS.md` and
   [run 31780073574](https://github.com/six2dez/drift/actions/runs/31780073574): the spawn `env`
   option **replaces** the parent block on Windows exactly as on POSIX (parent-only marker returned
   `PARENT-CLEARED`); libuv back-fills only eleven `required_vars` and `APPDATA`/`LOCALAPPDATA` are
   not among them, which are exactly what the Windows nvm/fnm candidate paths need. Therefore
   `{ ...driftVars }` without the parent spread is a defect on **either** platform.

Naming per C-6: `camelCase` functions with `get*`/`build*`/`normalize*` prefixes,
`SCREAMING_SNAKE_CASE` `as const` module constants, `type` over `interface`.

**Do not** add a `platform !== "win32"` guard anywhere in this file. **Do not** import from
`./command-resolution` — that module is untouched in Phase 4 (D-03).

| Boundary | Description |
|----------|-------------|
| Caido backend (LLRT) → local filesystem temp root | The directory returned by `getTempRoot` will hold token-bearing runtime files; other local users are the adversary |
| Upgraded install → filesystem state left by the shipped 0.1.0 | Token-bearing `drift-mcp-*` directories written by the previous version cross this boundary unmanaged |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-02 | Information Disclosure | `getSweepRoots` | mitigate | Ship the legacy `/tmp` arm on non-`win32`. Without it, `os.tmpdir()` moves macOS to `/var/folders/…` and 0.1.0's token-bearing `/tmp/drift-mcp-*` directories are never swept again. Proven by the three `-t "getSweepRoots"` cases |
| T-04-01 | Information Disclosure / Elevation | `getTempRoot` consumers | transfer | The random component of the temp-dir name is plan 04-08's `genShortToken()`; `platform.ts` only supplies the root. Recorded here so the two are reviewed together |
| T-04-04 | Information Disclosure | `buildSpawnEnv` | mitigate | The function copies the parent block into a child environment and must never be used to *render* an environment into a log or diagnostic. It returns data only; no logging in this module (pure modules never touch `sdk.console`) |
| T-04-SC | Tampering | npm/pnpm installs | mitigate | Phase 4 installs **zero** packages (04-RESEARCH.md § *Package Legitimacy Audit*: not applicable). Any `pnpm add` in this plan is out of scope and must be rejected |
