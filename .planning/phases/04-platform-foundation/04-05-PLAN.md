**Two hazard shapes, two mechanisms — this is the mistake to avoid collapsing.**
- **Total volume** (sites 1-5): a runaway child grows a string without limit inside the Caido
  backend's heap. Mechanism: `createBoundedBuffer` / `appendBounded` / `renderBoundedBuffer` with a
  per-site cap and retention policy.
- **Unterminated line** (site 6, plus `claude-print.ts`'s buffer in plan 04-06, plus

  newline, so the only unbounded case is a remainder with no terminator. Site A's head/tail/both

  protocol framing. Mechanism: `drainCompleteLines`, which splits once and drops an over-cap
  remainder **whole**.

line**. `drainCompleteLines` fixes both problems in one pure, unit-tested function.

Exports:

1. `export type BoundedRetention = "head" | "tail" | "both";`

2. `export type BoundedBuffer = { head: string; tail: string; droppedChars: number; maxChars: number; retention: BoundedRetention };`
   A state object rather than a bare string, because the marker must carry a **cumulative** dropped
   count and re-parsing a previously-embedded marker out of a string on every append would be
   fragile. This matches the backend's proven `createXState(): PlainObject` + free-functions shape
   (`claude-print.ts:103-117`, `:140`).

3. `export function createBoundedBuffer(options: { maxChars: number; retention: BoundedRetention }): BoundedBuffer`
   — initialises `head: ""`, `tail: ""`, `droppedChars: 0`.

4. `export function appendBounded(buffer: BoundedBuffer, chunk: string): BoundedBuffer` — returns a
   **new** state object, never mutates. Policies:
   - `"head"`: fill `head` up to `maxChars`; any excess increments `droppedChars` and is discarded.
     `tail` stays `""`.
   - `"tail"`: append to `tail`, then drop from the **front** until `tail.length <= maxChars`,
     incrementing `droppedChars` by the number of characters dropped. `head` stays `""`.
   - `"both"`: `head` fills to `Math.floor(maxChars / 2)`; everything after that goes into `tail`,
     which is then trimmed from the front to `maxChars - head.length`, incrementing `droppedChars`.
   Below the cap, all three policies must leave `droppedChars` at `0` and produce
   `head + tail === previousText + chunk`.

5. `export const TRUNCATION_MARKER_PREFIX = "\n…[drift: truncated ";` and a helper
   `export function buildTruncationMarker(droppedChars: number): string` producing exactly
   `` `\n…[drift: truncated ${droppedChars} bytes]…\n` `` — one greppable string with the count
   embedded so a reader knows what they lost. Comment that the count is UTF-16 code units (JS string
   `.length`) while the marker says "bytes" — the wording is kept for greppability and the
   discrepancy is documented rather than silently wrong.

6. `export function renderBoundedBuffer(buffer: BoundedBuffer): string` — returns `head + tail` when
   `droppedChars === 0`, otherwise `head + buildTruncationMarker(droppedChars) + tail`.

7. The five per-site **total-volume** caps as exported constants, each with a one-line rationale
   comment:

8. `export const MCP_SELFTEST_LINE_MAX_CHARS = 4 * 1024 * 1024;` — the **unterminated-line** cap for

   and dropping a real one is worse than holding it briefly.

9. `export type LineDrainResult = { lines: string[]; remainder: string; droppedChars: number };` and
   `export function drainCompleteLines(input: { buffered: string; chunk: string; maxRemainderChars: number }): LineDrainResult`
   — pure. `const combined = input.buffered + input.chunk;` then **one** `combined.split("\n")`;
   `pop()` the last element as the candidate remainder; `lines` is the remaining parts `trim()`ed
   with empties dropped. When the candidate remainder's `.length` exceeds
   `input.maxRemainderChars`, return `remainder: ""` and `droppedChars: <that length>`; otherwise
   `remainder: <candidate>` and `droppedChars: 0`.

   - **Why the bound is on the remainder, not the combined buffer.** A buffer containing newlines
     drains naturally through the split, so the only unbounded case is a remainder with no
     terminator. Bounding the pre-split concatenation would drop legitimate complete lines.
