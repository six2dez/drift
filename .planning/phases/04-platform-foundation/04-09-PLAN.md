<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Spawned CLI / MCP child process → backend `stdout`/`stderr` pipes | Unbounded volume, shaped by target-application content, crosses into the Caido backend's heap |
| MCP server process → activity JSONL file → backend parser | Attacker-influenced tool results cross here; the reader must tolerate torn writes and bad JSON |
| Activity read → backend heap and event loop | A per-tick allocation and a per-tick full re-parse are both availability concerns on a single-threaded runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-05 | Denial of Service | the four `stdout`/`stderr` accumulators | mitigate | Each is capped by its exported constant (1 MiB head / 256 KiB tail for `spawnAndWait`; 2 MiB both-ends / 256 KiB tail for `sendCliMessage`) with a counted truncation marker |
| T-04-17 | Denial of Service (self) | overflow policy | mitigate | Truncate and keep reading; never kill the child. Explicitly diverges from Node's `child_process.exec` `maxBuffer` precedent |
| T-04-09 | Denial of Service | per-tick activity read | mitigate | `readActivityTick` clamps every read to `ACTIVITY_MAX_TICK_BYTES` and allocates exactly that much, replacing a whole-file `readFile` that grew with the turn |
| T-04-06 | Denial of Service | 250 ms tick CPU cost on the single-threaded event loop | mitigate | Reading only newly appended bytes removes the per-tick full re-parse. The event loop is what runs the RPC keep-alive the watchdog depends on |
| T-04-15 | Tampering | activity line parsing | mitigate | Tolerant parse preserved verbatim (bad JSON skipped, never thrown), and `seenActivityIds` is explicitly retained as the correctness backstop against re-delivery after a truncation reset |
| T-04-16 | Denial of Service | activity file handle lifetime | mitigate | `readActivityTick` opens and closes per tick; a held handle would block `rm(activityFilePath)` at `finalize()` on Windows with `EBUSY`, leaving a runtime file on disk |
| T-04-SC | Tampering | npm/pnpm installs | mitigate | Phase 4 installs zero packages; this plan adds only local module imports |
</threat_model>
