<objective>
Modify `packages/backend/src/claude-print.ts` — PERF-04 **site B**, the Claude `stream-json` line
buffer — and append new cases to `claude-print.test.ts`.

Purpose: this site's hazard is **not** total volume, so it does not use plan 04-05's
`bounded-buffer.ts`. It is two distinct problems that look like one:

1. A single never-terminated line grows `state.buffer` without bound.
2. `consumeClaudePrintChunk` (`claude-print.ts:153-160`) runs an `indexOf`/`slice` loop that copies
   the whole remainder **per line** and rescans from index 0 **per line**, plus a full object spread
   per line. Claude's `stream-json` emits many small events per chunk, so *k* is routinely 10-50 and
   the cost is O(k·n). Under Caido's single-threaded runtime that CPU cost blocks the very RPC
   keep-alive the watchdog depends on — which arguably makes the CPU fix more urgent than the memory
   bound.

Both fixes are required. Bounding without fixing the slicing caps the memory and leaves the stutter.

Output: modified `packages/backend/src/claude-print.ts`, extended
`packages/backend/src/claude-print.test.ts`.

Validation rows owned (04-VALIDATION.md): PERF-04 `-t "unterminated"` and the behaviour-identical

  <action>
Two changes, both confined to `ClaudePrintState`, `createClaudePrintState`, the
`consumeClaudePrintChunk` prologue and loop, and `finalizeClaudePrintOutput`. **Nothing else in the
file moves.**

**Change 1 — bound the buffer.**
- Add `export const CLAUDE_LINE_BUFFER_MAX_CHARS = 4 * 1024 * 1024;` as a module constant next to the
  existing `CLAUDE_ASSISTANT_RECOVERY_IDLE_MS`-style constants. Comment why 4 MiB is deliberately
  generous: a legitimate `tool_result` content block can be large, and dropping a real one is worse
  than holding it briefly.
- Add `droppedChars: number` to `ClaudePrintState` and initialise it to `0` in
  `createClaudePrintState()`.
- Apply the bound to the **remainder after splitting**, not to the concatenated buffer before it. A
  buffer containing newlines drains naturally through the split, so the only unbounded case is a
  remainder with no terminator. When the post-split remainder exceeds
  `CLAUDE_LINE_BUFFER_MAX_CHARS`, add its length to `droppedChars` and set the new buffer to `""`.
- **Drop the whole remainder; do not truncate and parse it.** Comment the reason: a truncated JSON
  line is unparseable and would just be swallowed by the existing `catch { continue; }`, turning a
  visible drop into a silent hole.

**Change 2 — split once.**
Replace the `while (newlineIndex !== -1)` loop at lines 153-160 with:
- one `const parts = combined.split("\n")` on the concatenated buffer,
- `const remainder = parts.pop() ?? ""` as the new buffer,
- a `for (const raw of parts)` loop whose body is **byte-identical in behaviour** to today's: `trim()`
  the line, `continue` on empty, `JSON.parse` inside a `try` that `continue`s on failure, then the
  existing per-event handling untouched,
- **one** `nextState = { ...nextState, buffer: remainder }` update after the loop instead of one
  spread per line.

Preserve every existing invariant exactly: the line is `.trim()`ed before parse, empty lines
`continue`, bad JSON `continue`s silently, and handler callbacks (`onText`, `onSessionId`) fire in
the same order with the same values. Do not change `pendingToolUseIds`, `messageStopped`,
`stopReason`, `usage`, `completed` or `isError` handling.

**Surface the drop.**
- Add `export function getClaudePrintDroppedChars(state: ClaudePrintState): number` following the
  style of `getClaudePrintUsage` (`claude-print.ts:322-346`).
- In `finalizeClaudePrintOutput`, append a notice **only when `state.droppedChars > 0`**, in the form
  `` `\n…[drift: dropped ${state.droppedChars} bytes of unterminated Claude stream output]` ``. The
  `> 0` guard is load-bearing: it guarantees the return value is unchanged for every existing test
  input, which is exactly what `04-VALIDATION.md`'s behaviour-identical regression row grades.

Do **not** import `./bounded-buffer` — site A's both-ends-with-marker policy is wrong here, and the
two sites are deliberately independent.
