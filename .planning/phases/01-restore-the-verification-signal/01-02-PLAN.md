<objective>
Close SIG-01's parity half: reinstall Web Storage in DOM test environments where vitest's
`populateGlobal()` skipped it on Node >= 25, and delete the dead `environmentMatchGlobs` block that
Vitest 4 silently ignores.

Purpose: with only the production guard, the suite is green everywhere — but for different reasons.
On Node <= 24 the ChatView tests walk the "token present" path; on Node >= 25 they walk the "no storage"
path. That is a matrix whose legs silently test different things, which is exactly the class of blind
spot this phase exists to eliminate. The shim removes the divergence for ~35 lines.

Output: `vitest.setup.ts` (new), `vitest.config.ts` rewired, and `packages/frontend/src/__storage-shim.test.ts`
proving the shim is inert when storage already works (SIG-01i).
</objective>

**Create `vitest.setup.ts` at the repo root.** Implement RESEARCH `### Pattern 2` exactly. Required elements:

- A file header comment in the repo's "why, not what" style that names the external constraint and the exit
  condition. It must state: Node >= 25.0.0 unflagged Web Storage so `localStorage` now exists on the Node
  global; vitest's `populateGlobal()` skips any happy-dom window property whose name already exists on the
  Node global and is not in its explicit `KEYS` list; `localStorage`/`sessionStorage` are not in that list
  (verified: `grep -c localStorage` over vitest 4.0.18's and 4.1.10's environment chunk returns 0). Cite
  upstream `vitest-dev/vitest#8757` (closed: "non-LTS is not officially supported") and
  `capricorn86/happy-dom#1950` (open). End with: **DELETE THIS FILE when the repo upgrades to Vitest >= 5**
  (v5 adds `localStorage` to `OTHER_KEYS`; re-verify `sessionStorage`, which v5 still does not list).
- `type StorageLike` with `readonly length: number`, `key`, `getItem`, `setItem`, `removeItem`, `clear`.
- `function hasUsableStorage(name: "localStorage" | "sessionStorage"): boolean` — reads
  `(globalThis as Record<string, unknown>)[name]` inside a try/catch, returns `false` for
  `undefined`/`null`/non-function `getItem`, and `false` if the property access itself throws.
- `function createStorage(): StorageLike` — reads `(globalThis as { Storage?: new () => StorageLike }).Storage`;
  if it is a function, `return new Ctor()` **inside a try/catch**; on throw, fall through to an in-memory
  `Map<string, string>` implementation providing `get length()`, `key(index)` via `[...entries.keys()][index] ?? null`,
  `getItem` returning `?? null`, `setItem` coercing both args with `String(...)`, `removeItem`, and `clear`.
- The install block, gated on `typeof (globalThis as { document?: unknown }).document !== "undefined"`,
  looping `for (const name of ["localStorage", "sessionStorage"] as const)` and, when `!hasUsableStorage(name)`,
  calling `Object.defineProperty(globalThis, name, { value: createStorage(), configurable: true, writable: true })`.

**Both guard clauses are mandatory and were measured necessary.** Without the `typeof document !== "undefined"`
gate, the shim runs in node-env files where `globalThis.Storage` is Node's native class, and `new Storage()`
throws `Illegal constructor` -> **15 of 22 test files fail to collect**. Without the try/catch around
`new Ctor()`, same outcome. Do not "simplify" either one away.
