<objective>
Turn CI from a single Node 20 leg on `main` into a four-leg matrix on every branch, with lint wired in
and no `--fix` anywhere.

Purpose: this entire phase exists because a single-version pin hid a runtime behaviour change. The matrix
IS the control. Node 26 is the only leg that reproduces the bug; without it the ROADMAP's original
20/22/24 matrix would ship green and leave the defect live on Current. The `branches: [main]` filter is
the second half of the blind spot — a workflow only runs from the branch it exists on, so today no feature
branch is ever verified.

The action major bumps land here rather than in Phase 9: Phase 9 rewrites this same workflow to add
`windows-latest`, all four `@v4` pins run on the deprecated Node 20 actions runtime (default-switched
2026-06-16, removed fall 2026), and a deprecation banner on every run erodes exactly the signal this phase
is restoring.

Output: a restructured `ci.yml` and a `release.yml` that gains the same lint step, with the signing
pipeline untouched.

HAND-OFF (assumption A7, human, outside git): renaming the job's display name from
`Typecheck, test, build` to four `Verify (Node N)` names changes the GitHub branch-protection
required-check names. If `main` requires the old name and it is not updated, `main` is left
merge-unguarded. This is NOT a task this plan can complete — it is carried into plan `01-06` task 3.
</objective>
