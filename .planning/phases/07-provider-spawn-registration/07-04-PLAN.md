<objective>
Make `mcp remove` a guarantee rather than a hope.

07-03 moved a live Caido session token into two external CLI configuration files that live outside
the temp root Drift sweeps and outside the accepted per-user temp permission baseline. This plan is
the other half of that trade: an unconditional dual-scope sweep at every MCP start, a removal on
cleanup that covers every scope, and a failed removal that surfaces as a security event the user can
actually see.

Purpose: SC-3's "a failed remove is logged, not dropped", and the concrete closure of the phase's
highest-severity threat. Output: a pure removal-policy builder and a value-free failure formatter,
a startup sweep sibling to the existing orphan sweep, and the stale comments at three seams corrected
to match the code.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| An external CLI's persistent configuration file -> the host filesystem over time | A registration entry holding a live credential rests in a home-directory file across process lifetimes, backups and profile syncs. |
| A removal spawn's result -> Drift's user-visible reason map and the support bundle | Failure information crosses into a surface a user can read and export. |
| Process lifetime boundary | An entry written by one Drift run must be removable by a different Drift run that has no memory of writing it. |
