<objective>
Promote provider status from a presence boolean to a capability level, and give the phase its single
source of truth for what each CLI can actually do with Drift's MCP server.

This plan expands from 07-01's proven spawn slice into the layer every later plan reads: 07-03's Codex
allowlist and 07-04's failure sentences both consume the table this plan creates, and both write into
the wire this plan opens between `skippedMcpCliReasons` and the provider card.

Purpose: a registered-but-limited Codex is a genuinely working provider. Today's shape cannot say
that — `available` is a boolean and the only advisory channel is `error`, which paints the dot red and
tells the user something false.
Output: the capability type and predicate in `packages/shared/src`, every consumer migrated, the
in-product sentence rendered, and the MCP server's refusal message upgraded.
</objective>

<assumption_delta_decision>
**Primary noun:** *what this provider can do* — the provider's capability level — not *is the provider
present*.

**Decision: PROMOTE.** `ProviderStatus.available: boolean` is replaced by a capability level, and the
boolean survives only as a derived read through a shared predicate. It is not added alongside.

**Rationale (one line):** a registered-but-limited Codex is `available: true` today, so D-08's
limitation sentence has nowhere truthful to live — riding `error` turns the status dot red and tells a
user their working provider is broken, and adding a fourth optional field beside a boolean that
already answers a narrower question leaves two overlapping truths for every consumer to reconcile.

**Type shape (planner's call; the promote-vs-add-alongside decision is the user's and is settled):**
the field is named `capability`, not `status`, because the containing type is already called
`ProviderStatus` and `status.status` is unreadable at every call site. `capability` takes
`"available" | "limited" | "unavailable"`, and an optional `limitation` string carries the sentence
that explains a `"limited"` reading. `available` is removed outright rather than deprecated: leaving
it would let a stale consumer keep compiling against the narrower question, and its removal is what
turns every unmigrated read into a compile error instead of a silent behaviour gap.

**Suggested companion (not required by the checkpoint):** an invariant test asserting
`isProviderUsable` agrees with the capability level for EVERY member of the union — driven from an
exhaustive record keyed by the union so a future fourth member is a compile error rather than an
untested branch. That test encodes the generalized intent (usability is derived from capability) as a
contract rather than as a convention.

**Reversibility:** costly. Undoing it means re-deciding the surface and unpicking the widened meaning
of `skippedMcpCliReasons` from whatever sentences ship — the same coupling D-08 already flagged.
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| External CLI process -> Drift's user-visible reason strings | Text originating outside Drift (a CLI's own stderr, echoed into the skip-reason map today) crosses into the provider card and the support bundle. |
| MCP server -> the CLI's transcript | The refusal message this plan upgrades is rendered inside the user's AI CLI session and may be echoed further by that CLI. |
| Shared capability table -> the tool policy actually sent to a CLI | One data table decides which tools a CLI is offered; a wrong or missing entry decides a security posture. |
