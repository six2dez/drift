## Recorded decisions

**D-P1 — the line-ordering assertion is an in-test `functionBody` helper, not an `awk`+`sed` shell gate.**
`08-PATTERNS.md` § *No Analog Found* flags this sub-pattern as having no precedent: `callArgumentTexts`
returns argument *text* and discards offsets, so nothing in this repository asserts statement **order**
inside `index.ts`. Two options were open. The `awk '/^async function X/,/^}/' | sed 's://.*::'` shell
gate that `08-VALIDATION.md` seeds is rejected as the **primary** control for two reasons: `sed 's://.*::'`
strips `//` occurring **inside string literals** — and `index.ts` carries URLs and Windows UNC-shaped
paths — which is exactly the corruption `index.source.test.ts`'s whole-line-only `stripCommentLines`
(lines 36-53) was written to avoid; and a shell gate runs only where someone remembers to run it, while a
vitest assertion runs on all five CI legs unprompted. A `functionBody(code, name)` helper modelled on the
existing balanced-paren scanner is therefore the gate. The shell form is kept in the plan's
`<verify>` block as a second, independent read of the same fact — two different scanners agreeing is
stronger than either alone — but it is not what the phase's evidence rests on.
*Reversibility: reversible — a test helper with three call sites.*

**Pitfall 4 — the second rung is kept on both platforms, and is a re-issue of the same plan on Windows.**
Under LLRT the Windows arm of the child handle's own `kill` consumes its sender on first use, so a second
direct signal there is **inert**, and every signal name maps to one `TerminateProcess` anyway — the code
would read as graceful-then-forceful while being forceful-then-nothing. Routing the second rung through
`killTree` fixes that by construction: on win32 both rungs build the identical `/t /f` plan, so the second
rung is a real re-issue against a pid that has normally already gone, and on POSIX the two rungs are
genuinely different signals to the group. Say this in the source at both two-rung sites so a later reader
neither deletes the rung as redundant nor restores a direct handle signal.
*Reversibility: reversible.*

**Pitfall 10 — in the timeout handler, move the kill up; never move `finalize`.**
`finalize` is a `const` arrow declared lower in the same promise executor, and `index.ts:4252-4256`
records a real bug from calling it earlier: the temporal dead zone throws a `ReferenceError`
synchronously inside the executor. Only two statements are swapped, and `finalize`'s declaration site is
not touched.
*Reversibility: reversible.*

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| live MCP child ↔ its env-source files on disk | The MCP server polls `DRIFT_APPROVALS_FILE` synchronously before every sensitive tool. Removing that file while the process lives destroys evidence without removing capability. |
| `stopMcpServer` / `startMcpServer` failure path → `cleanupMcpRuntime` | Both reach the same teardown; a fix that only covered the Stop button would leave the failure path exposed. |
| deferred timer callback → OS process table | A 3000 ms-later kill acts on a pid whose owner may have changed. |
