<objective>
Produce the Windows half of this phase's evidence, on the only Windows vehicle this project has: the
blocking `windows-latest` CI leg.

Two things are proven here and they are different in strength. The **mechanism** is proven
behaviourally: on a real Windows host, the argv `buildKillTreePlan` produces brings down a live parent
and its grandchild. The **undocumented exit code** for an already-dead pid is *measured and recorded*,
not asserted — Microsoft documents none, and `08-RESEARCH.md` assumption A2 warns that branching on it
turns a low risk into a high one.

Then both are protected from the failure mode that makes a Windows gate worthless: going green because
nothing ran. A `--reporter=json` step reads the executed count out of the Windows host, and an
every-platform gate test asserts that step still exists and still points at a file that exists — so a
deleted gate is noticed on the Linux legs, where someone is looking.

Purpose: LIF-01 has no local vehicle. Every claim it makes has to be earned on a runner.
Output: the win32 integration suite, its false-green gate, and the CI step that executes it.

## Recorded decisions

**D-P2 — the two Windows gate steps are made mutually non-satisfiable, by name.**
`08-PATTERNS.md` flags the collision: both gate tests assert with `toContain` against the whole `ci.yml`
text, and Phase 7's test already asserts `--reporter=json`, `pending > 0`, `total === 0` and
`passed !== total`. If Phase 8 reuses those strings and no distinct anchor, each suite passes against the
*other* step — so deleting either step leaves both tests green. Phase 8's anchors are therefore fixed as:
step name `Gate: the win32 kill-tree suite actually ran`; report path
`$RUNNER_TEMP/win32-kill-tree-report.json`; suite path `packages/backend/src/kill-tree.win32.test.ts`;
and the two console strings reading "the win32 kill-tree suite". Each gate test asserts its own four
anchors, and Phase 8's additionally asserts that **both** step names and **both** report filenames are
present — the direct closure of the collision.
*Reversibility: reversible — string constants in two test files and one workflow.*

**D-P4b — the undocumented exit code is recorded, never asserted (no precedent; specified here).**
`08-PATTERNS.md` § *No Analog Found* records that the measurement-with-run-URL **style** is precedented
(`spawn-plan.ts:47-62` and `spawn-plan.win32.test.ts:213-232`) but the "record, do not assert" **shape**
is not: the existing precedent records a boolean round-trip, not a numeric vendor exit code. The shape is
fixed as: capture `{ code, stderrFirstLine }`; assert only that a number came back (`typeof code === "number"`),
which proves the binary resolved and ran; emit one `console.log` line prefixed `[measurement]` carrying
the two values so they appear in the runner log; and leave a comment block in the file reserving the
place where the measured value and its run URL are written after the first real `windows-latest` run,
exactly as `spawn-plan.ts`'s header reserves its RED and GREEN URLs. No `expect` compares `code` to a
literal, in this file or anywhere else.
*Reversibility: reversible.*
