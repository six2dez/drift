## Atomic scope justification and task ownership

This plan intentionally owns eleven paths as one ordered record-convergence transaction. Task 1 owns only `verdict-gate.sh` and `08-VALIDATION.md`; Task 2 owns only the three backend comment carriers plus STATE/WINDOWS; Task 3 owns only SECURITY, ROADMAP, REQUIREMENTS, and `deferred-items.md`. The gate and its committed-summary pins must become strict before any carrier changes, and the dependent Plan 08-19 must consume the same SECURITY/gate state after convergence. Splitting pointer/deferred work into another plan would create a second overlapping `verdict-gate.sh` / `08-SECURITY.md` / `deferred-items.md` handoff and a race over which intermediate red state is authoritative; strict per-task ownership and the existing wave-11 → wave-12 dependency are the safer atomic boundary.
