## The correction convention, and the gate that enforces it

Every correction follows the `07-VALIDATION.md` style already used at `08-SPIKE.md` § *Step 3*:
the superseded text stays visible, dated, with its replacement beside it. Nothing is silently
overwritten — that is how the phase can still tell measured ground from assumed ground.

To make the convention machine-checkable, **superseded text is preserved inside a markdown
block quote, every line beginning with `>`.** The active statement sits outside the quote. A
gate then strips the quote layer and asserts the stale verdict is absent from the active text
— the same technique `index.source.test.ts` already applies to comments in source. Put a stale
verdict back outside a block quote and the gate goes red.

## The G-03 treatment rule, written down because the gap asks for the reasoning

**Corrected in place — `08-VERIFICATION.md` and `08-RESEARCH.md`.** Both are living reference
documents that later work reads: the verifier's human-test list is what a re-run consults, and
RESEARCH's Validation Architecture is inherited by Phases 9 and 10. A document that will be
*followed* must be correct.

**Annotated as superseded, never rewritten — `08-01-PLAN.md` and `08-05-PLAN.md`.** An executed

the record disagree with what was run and would destroy the audit trail this gap depends on:
the finding is precisely that a wrong command travelled unchanged through five gates, and that
finding is only legible while the plans still show what they said. They get a dated pointer to
the corrected procedure and nothing else.

## The two open decisions, decided here

**SC-4's completion-order clause — DECLARED as a residual, and the verifier's alternative was
considered and rejected.** SC-4's statement ORDER is enforced by code and independently
verified at all three sites, but its "so token-bearing processes die before their env-source
files are removed" clause is not: `killTree` is fire-and-forget by design and the removals are
unawaited. The verifier offered two options — declare it, or await the killer in
`cleanupMcpRuntime` where the call site is already async. **Awaiting is rejected**, and not for
convenience: awaiting a spawned killer inside an RPC handler suspends that handler while
waiting on a child-process callback and a timer that Caido's runtime does not reliably deliver
during an await. That is the event-loop starvation CLAUDE.md names as an anti-pattern and the
reason `killTree` is fire-and-forget in the first place (OQ-4, T-08-13). So the clause is
declared as **AR-05**, with the one thing that genuinely improved recorded alongside it: the
reaper plans 08-06 and 08-07 shipped identifies its target by the target's own argv rather than
by anything on disk, so unlike `killTree` it is INSENSITIVE to losing that race. Statement
order is still enforced, and now enforced for the reap as well as for the kill.

**The win32 orphan class — DECLARED as AR-04.** `taskkill /t` walks `ParentProcessId` and is
indifferent to process groups, so A6 was never a Windows question and LIF-01's mechanism is
unaffected. What Windows does not get is the G-04 class: an MCP server launched by a CLI
instance Drift did not spawn. Reaching it needs a command-line enumerator, and the three
candidates were each rejected with a reason — `tasklist` does not print command lines, `wmic`
is removed from current Windows, and spawning PowerShell from the plugin opens a surface this
phase will not open. Recorded with an owner rather than left as an absence.
