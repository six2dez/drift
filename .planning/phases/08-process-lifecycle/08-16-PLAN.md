<objective>
Take the four readings that only the maintainer's hardware can produce, on the build that ships.

`08-VERIFICATION.md` ranks one of these as **"the cheapest high-value measurement in the phase: one
cancel and one glance"** — reading the orphan reap's outcome after a cancel. If it reports that the
enumerator could not be spawned, the entire mechanism plans 08-06/08-07 built is inert on the
shipping runtime while every gate in the repository stays green. Plan 08-15 put that outcome into the
diagnostics panel so it costs a glance instead of a spike.

The other three are the ones SC-3 and both requirements name and nothing has ever run: the POSIX
cancel path re-measured after the fix that shipped for UAT gap G-04, the POSIX absolute-timeout path
which has never been exercised at all, and A6 against a Drift-spawned Claude Code turn — the
maintainer's active provider, unmeasured in either direction, where the existing falsification covers
codex on an instance Drift did not spawn.

This plan is `autonomous: false` and its measurement task carries a gate that cannot be auto-approved
in any mode. That is deliberate and it is the whole point: this phase's defining defect is a
favourable answer produced where no answer was possible, and the cheapest way to repeat it would be
an unattended run recording a measurement nobody took.

Purpose: gap 3 `missing` items 2 and 3, and `human_verification` items 2, 3 and 4.
Output: four readings on real hardware, or four dated abstentions that say exactly what stopped them.
</objective>
