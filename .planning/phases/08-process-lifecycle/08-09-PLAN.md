<objective>
Close **G-05**. `mcp-context.json` is written at `index.ts:1181-1184` with no `mode` option
and lands at `0644` (`-rw-r--r--`, observed on disk 2026-08-27), while `CLAUDE.md:123` states
that sensitive temp files — MCP config and context file — are `0o600`.

The gap explicitly asks for the omission to be traced rather than patched at the one place it
was observed. It was, and there are **five** writes into the MCP temp directory with no mode,
not one:

| Site | File | What it carries | Consequence of world-readable |
|---|---|---|---|
| `writeMcpContextFile` | `mcp-context.json` | project id, history filter, context override | the observed gap; information disclosure |
| `createSessionRuntimeFiles` | `mcp-activity-<id>.jsonl` | tool activity, including request and response material drawn from the user's Caido history | information disclosure |
| `createSessionRuntimeFiles` | `mcp-approvals-<id>.json` | the approval decisions the MCP server polls before running a sensitive tool | **world-WRITABLE would let another local user pre-approve a sensitive tool** |
| `writeApprovalDecision` | the same approvals file, rewritten | as above | as above |
| `startMcpServer` staging | `mcp-server.mjs` | **executable code that is then run by node with `CAIDO_TOKEN` in its environment** | the most severe: local code execution carrying the token |

The one that was observed is the least severe of the five. The `mcp-server.mjs` copy is the
most severe and was not observed at all — which is exactly why the gap asked the question in
the general form.

Every one of them sits inside a `0o700` parent directory that `enforceOwnerOnlyDir` asserts
post-creation, so on POSIX this is one defense-in-depth layer being thinner than documented,
not an exposure. It is still worth closing: the directory guarantee holds only for a directory
Drift itself created, `mkdir` with `recursive` does not apply a mode to a directory that
already exists, and the assertion that covers that case is skipped on win32.

**The Windows position, recorded as an accepted trade-off rather than left implicit.** POSIX
mode bits are ignored on Windows, so none of these five options changes anything there — the
house rule (T-04-30) keeps them unconditional anyway, because LLRT's mode setter is a total
no-op off unix and a platform guard would double the branch count for zero behaviour change
while risking a POSIX regression. What protects these files on Windows is that
`os.tmpdir()` there resolves to the per-user temp directory beneath the user's profile, which
Windows already ACLs to that user. That is the Windows-appropriate equivalent CLAUDE.md's
constraint asks for, it is already in place by construction, and this plan records it as an
accepted trade-off with its reasoning rather than leaving a reader to wonder whether the
question was asked.

Purpose: make the on-disk state match the documented rule at every site, not only the one
someone looked at. Output: five explicit modes, one recorded trade-off, one census gate.
</objective>
