# Phase 8 — UI Design Contract

> Visual and interaction contract. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Why This Document Exists (read first)

Phase 8 is a **backend process-lifecycle phase**. Ten plans have shipped and **zero files under
`packages/frontend` or `packages/shared` were modified** — `08-VERIFICATION.md` records this as a
VERIFIED PROHIBITION (`git log --name-only` over the phase: zero files in either).

The UI plan gate that triggered `/gsd-ui-phase` was a **prose false positive**: it matched the word
*"form"* inside ROADMAP SC-1's amendment note ("SC-1 as originally written was satisfied by the
insecure **form**"). There is no form, no screen and no new component in this phase.

The maintainer chose to generate this spec anyway rather than pass `--skip-ui`. So this document
does exactly two things, and deliberately no more:

- **§ A — the unchanged-surface regression contract.** ROADMAP **SC-5** ("macOS/Linux cancellation
  and timeout semantics *visible to the user* are unchanged") is a UI claim with no artifact behind
  it. § A turns it into checkable statements about components that already exist.
- **§ B — one design decision (UD-01), now RESOLVED.** Whether the orphan reap's
  `reason=enumerator-unavailable` outcome deserves any user-visible surface. Referred to the
  maintainer rather than decided by the researcher, and **answered 2026-08-28: option C —
  a diagnostics-only `getDiagnostics()` key, no user-visible surface, zero frontend files.**

**There is no `08-CONTEXT.md`.** It was never created across ten executed plans. Nothing in this
document was lifted from one; every locked row below was read out of source or out of
`08-VERIFICATION.md` / `08-UAT.md` / ROADMAP.md and carries its `file:line`.

**This spec adds no component, no screen, no token and no copy string.** If a Phase 8 gap-closure
plan finds itself editing a `.vue` file to satisfy this document, that plan is wrong — except under
§ B option **A** or **B**, which are not selected.

## Color

**Drift owns no palette.** `@caido/tailwindcss` maps every `surface-*` class to a host CSS custom
property — `surface: { 100: "hsl(var(--c-surface-100))", … 900: … }`
(`node_modules/@caido/tailwindcss/dist/tailwindcss.js:111-120`). **There is no hex value for the
dominant or secondary surface anywhere in this repository**, and there must not be: the host theme
resolves them, and hard-coding one would break Caido's light/dark switch.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--c-surface-900/800)` via `bg-surface-*` (host-resolved) | app background, chat transcript, panel bodies |
| Secondary (30%) | `var(--c-surface-700/600)` via `border-surface-700`, PrimeVue `Card` body | Settings cards, Help cards, status strip, borders |
| Text ramp | `text-surface-100` → `text-surface-500` (host-resolved) | 100 = primary label, 200 = provider name, 300 = help body, 400/500 = the `CliStatus` detail lines |
| Accent (10%) — semantic only | `green-500/700/300`, `yellow-500`, `amber-400/700/300`, `red-400/800/300` | see reserved-for list below |
| Destructive | PrimeVue `severity="danger"` (host-themed red); `text-red-400` for error prose | Stop button; MCP auth-error message |

**Accent is reserved for exactly these elements — never for generic interactive affordance:**

1. `green-500` — `CliStatus.vue` status dot when **not** streaming ("Ready").
2. `yellow-500` — `CliStatus.vue` status dot **and** the "Streaming..." word while a turn runs.
3. `green-500` / `red-500` — `ChatInput.vue` provider-availability dot (`fa-circle`), pass/fail only.
4. `amber-400` — `CliStatus.vue` "Override active" chip, when a Caido context override is in force.
5. `green-700/300` — `App.vue` MCP badge when the server is running (`MCP n/m`).
6. `amber-700/300` — `App.vue` MCP badge when stopped or checking (`MCP Stopped` / `MCP Checking`).
7. `red-800/300` — `App.vue` MCP badge on `authState === "invalid" | "error"` (`MCP Auth Error`).
8. `surface-600/500` — `App.vue` MCP badge when MCP is disabled (deliberately **not** accent).
9. `red-400` — the MCP auth-failure sentence in `SettingsView.vue`.
10. `severity="danger"` — the **Stop** button, and only while `isStreaming` is true.

**Phase 8 contract:** the accent list above is **closed**. No Phase 8 plan may introduce a new
accent colour or reuse one of these ten for a different meaning. In particular, if § B UD-01 is
resolved toward a visible signal, it must reuse `amber-*` (the established "degraded but running"
meaning, rows 4 and 6) and must **not** use red — the reap failing closed into a no-op is a
capability gap, not an error.

## § B — UD-01 (RESOLVED): does `enumerator-unavailable` get a user-visible surface?

> **DECIDED 2026-08-28 by the maintainer (six2dez): option C — diagnostics-only field.**
> No user-visible surface. Add one key to the `getDiagnostics()` record carrying the last orphan-reap
> outcome (e.g. `lastOrphanReap: "noop reason=enumerator-unavailable killed=0"`), keep the existing
> backend console lines unchanged, and change **zero** files under `packages/frontend` or
> `packages/shared` — `SettingsView.vue:676-677` renders the diagnostics record generically
> (`v-for="(value, key) in diagnostics"`), so a new key needs no frontend edit.
>
> **Rationale.** C is the only option that lets a user or a bug reporter answer *"is the reap inert on
> my machine?"* without touching the UI, so § A/R-10 and ROADMAP SC-5 both survive intact and no
> Phase 8 gap-closure plan has to enter `packages/frontend`. It matches what `08-VERIFICATION.md`
> actually asks for — a **retrievable reading**, not an alert. Its weakness is accepted and recorded
> rather than argued away: diagnostics is user-triggered and after-the-fact, so it never *tells*
> anyone; it only answers someone who thought to ask. A/B were rejected as scope expansion into a
> deliberately quiet UI for a condition that fails **closed** (a capability gap, not a regression —
> the posture with it is exactly the pre-Phase-8 posture); A additionally carries the per-cancel
> alarm-fatigue failure mode. D was rejected because it leaves the fact discoverable only by someone
> who already knows to open the backend console, which is the status quo the verification report
> named as a problem.
>
> **Consequences of choosing C — all of them are "no change":** § A/R-10 needs **no** marked
> exception; ROADMAP SC-5 needs **no** amendment; the § Color, § Typography and § Copywriting
> contracts are untouched. Sub-question 1 is resolved as recommended — **only the inert case is
> load-bearing**; the diagnostics key records whatever the last reap was, but nothing is ever pushed
> at the user, so the "train users to ignore the channel" risk does not arise. Sub-questions 2 and 3
> (colour, alert copy) are **moot** — they applied only to A/B.
>
> **Carried into planning as a locked decision.** The `lastOrphanReap` key is backend-only work for
> the `/gsd-plan-phase 8 --gaps` round; it is not a licensed reason to open a frontend file.

**Status: RESOLVED — option C. The analysis below is preserved as written for the record.**

### The situation

Plans 08-06/08-07 shipped an argv-marker orphan reap that kills Drift's own leaked, token-bearing
MCP children by temp-directory identity. Its entire user-facing output today is one line in the
**Caido backend console**:

```
[drift lifecycle] orphan reap: kind=noop reason=<reason> exit=<n> killed=0
[drift lifecycle] orphan reap: kind=reap exit=<n> killed=<n>
[drift lifecycle] no orphan reap: <plan-refusal-reason>
[drift lifecycle] no orphan reap: gate-closed sessions=<n> directDepth=<n>
```
*(`index.ts:3776`, `:3823`, `:3853`, `:3979` — scalars only, no pid, no path, no argv, by the
T-04-04 rendering rule.)*

One of those reasons matters far more than the rest. **`reason=enumerator-unavailable` means
Caido's sandbox could not spawn `pgrep`** — i.e. the entire gap-closure mechanism is **inert on the
shipping runtime**, while every CI gate stays green. `08-VERIFICATION.md` names this in the phase's
own words ("may degrade silently to the enumerator-unavailable no-op while every gate stays green",
ledger entries 14/15) and calls checking for it *"the cheapest high-value measurement in the phase:
one cancel and one glance"*. Corroborating detail from the same report: `pgrep` and `kill` are
spawned by **bare name**, and the one real-hardware diagnostics run showed the existing bare-name
`which` lookup produced **no** result — so bare-name resolution in the sandbox is genuinely
unconfirmed, not merely unmeasured.

**Today a user has no way to know.** Nothing outside the backend console distinguishes "the reap ran
and found nothing" from "the reap cannot run at all on your machine".

### The tension — both sides are real

**For a surface:** Drift's users are pentesters, and the files being cleaned up carry the **Caido
session token**. A silently-inert token-cleanup mechanism is a security-relevant fact *about the
user's own machine*, and the person best placed to act on it is the user. The project's own
verification report ranks discovering this as the #2 highest-value open action in the phase.

**Against a surface:** Caido's chat UI is deliberately quiet, and **this phase's SC-5 promises the
visible semantics are UNCHANGED**. Adding a surface is a real (small) scope expansion into
`packages/frontend`, breaking a prohibition that ten plans have kept and that § A/R-10 argues is the
cheapest proof SC-5 holds. `enumerator-unavailable` also fails **closed** into a no-op that removes
no pre-existing code path — it is a capability gap, not a regression, and the security posture with
it is exactly the pre-Phase-8 posture.

### The options, costed

| # | Option | Frontend files changed | Effect on § A / SC-5 | Cost |
|---|--------|------------------------|----------------------|------|
| **A** | **Persistent degraded-capability indicator** — e.g. an `amber-400` chip in `CliStatus.vue` beside "Override active", or a line in the Settings MCP panel, shown whenever the last reap reported `enumerator-unavailable`. | 1–2 (`CliStatus.vue` and/or `SettingsView.vue`) + a `shared` type field | **Breaks R-10.** SC-5 needs an amendment: the visible semantics *do* change. | Highest. New state plumbing backend → `shared` → store → component; a new always-on chip in a deliberately quiet UI; risk of alarm fatigue since it fires on every cancel on an affected machine. |
| **B** | **One-time notice** — surface it once per Caido session (first time the reap reports `enumerator-unavailable`), then stay quiet. | 1 + a `shared` field | **Breaks R-10**, but SC-5 stays defensible: the steady-state semantics are unchanged. | Medium-high. Needs a "seen" flag with a lifetime nobody has specified; a notice the user dismisses before reading is worse than the console line. |
| **C** ✅ **CHOSEN** | **Diagnostics-only field** — add a key to the `getDiagnostics()` record (e.g. `lastOrphanReap: "noop reason=enumerator-unavailable killed=0"`). `SettingsView.vue:676-677` already renders the diagnostics record **generically** (`v-for="(value, key) in diagnostics"`), so a new key needs **no frontend edit at all**. | **0** | **R-10 holds. SC-5 holds** — nothing in the chat surface changes. | Low. One backend `let` + one record entry. | **D** | **Console-only — change nothing.** Optionally add one line of Help copy telling a user where to look. | 0 (or 1 if the Help line is added) | R-10 and SC-5 hold trivially. | Lowest. Leaves the fact discoverable only by a maintainer who already knows to look. |

### Sub-questions the answer must also resolve

1. **Do successful reaps ever surface, or only the inert case?** Recommendation regardless of
   option: **only the inert case**. `kind=reap killed=3` is normal operation and is console-worthy,
   not UI-worthy; surfacing it would train users to ignore the channel.
2. **If A or B: which colour?** Constrained by the § Color contract to `amber-*` (rows 4 and 6 —
   "degraded but running"), never red.
3. **If A: exact copy.** Must state the *consequence*, not the mechanism. A user cannot act on
   "pgrep unavailable". Draft: `Orphan cleanup unavailable — Drift cannot enumerate processes on
   this machine, so a leftover MCP process may survive a cancelled turn.` *(Not locked; only
   applicable if A is selected.)*

### Researcher recommendation (advisory, not a decision)

**Option C**, plus keeping the existing console line. It is the only option that gives the user a
way to answer *"is the reap inert on my machine?"* while **changing zero frontend files**, so
§ A/R-10 and SC-5 both survive intact and no Phase 8 gap-closure plan has to touch the UI. It also
matches what the verification report actually asks for — a reading a maintainer or a bug reporter
can retrieve — rather than an alert. Its honest weakness, stated: diagnostics is **user-triggered
and after-the-fact**, so it never *tells* anyone; it only answers someone who thought to ask.

**If the maintainer weighs "pentester deserves to know their token cleanup is inert" above "the UI
stays quiet", the answer is B, not A** — A's per-cancel chip on an affected machine is the
alarm-fatigue failure mode.

**Recording the answer:** amend this section in place with the chosen option, the date and the
rationale — the project's established marked-correction convention — and flip
`open_decisions: 0` in the frontmatter. If the answer is **A** or **B**, § A/R-10 must gain a
marked exception and ROADMAP SC-5 must be amended in place naming the new visible element,

## UI Considerations

State coverage for the surface Phase 8's guarantees touch, produced by the **UI-consideration probe**
(`ui-consideration-probe.cjs`, run 2026-08-28 after checker approval — never inline during authoring,
so a revision-loop rewrite cannot clobber it). Six surfaces were classified into the closed 8-category
shape-rooted taxonomy. **No new state is introduced by this phase**; every resolved row below is an
existing state held to a regression baseline.

**Kind-confirmation override (the partial-cue mitigation, and it mattered here).** The prose
classifier is heuristic and lossy. It classified **E2** (`CliStatus` strip) and **E5** (App MCP badge)
as `static-content` **only**, raising just `overflow`/`long-text` — so the surface that actually
renders the timeout and cancel reason strings was never asked what it shows while loading or on error.
The maintainer confirmed `interactive-control` on both (2026-08-28), which raised their `loading` and
