Run the probe on a real `windows-latest` host and capture what it measured. This plan is the phase's completion bar: per D-13 the phase is complete only when a real CI run has produced all seven assertion lines, recorded with its URL. "The files exist and the YAML is valid" is explicitly not sufficient — that is the false-green pattern Phase 1 existed to eliminate.

Plan 03-05 writes the committed findings document from these measurements and from nothing else (D-12).

Before pushing anything, this plan re-runs the local gates. A lint error in `scripts/windows-llrt-probe.mjs` would turn all four pre-existing `Verify (Node N)` legs red, so the pre-flight is what keeps a probe defect from masquerading as a quality-gate regression.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local working tree → public `origin` | Anything pushed to a scratch branch on a public repository is world-visible, and remains so in run records after branch deletion |
| GitHub Actions run record → project evidence | The run's conclusions become the basis for Phase 4's architecture; a misread or fabricated conclusion propagates silently |
| runner environment → public artifact | The probe's stdout becomes a downloadable, world-readable artifact |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-05 | Information Disclosure | pushing to a public remote | mitigate | The scratch branch is created at an already-committed SHA, so the push adds no new content. Only targeted `git add <path>` is used if a fix commit becomes necessary, never `git add -A` (STATE.md, decision `[01-06]`). Branch names use the `scratch/ci-proof-*` form so a single glob confirms none survive; teardown and its assertion are plan 03-04's final task |
| T-03-06 | Tampering | integrity of the recorded verification signal | mitigate | Per-step conclusions are read from `gh run view --json jobs` rather than inferred from the YAML, and the seven assertion lines are taken verbatim from the downloaded artifact rather than paraphrased. The log cross-check strips ANSI escapes before grepping, closing the failure mode recorded in `01-06` where a grep that matched nothing was indistinguishable from a proof that failed |
| T-03-11 | Repudiation | a non-zero probe exit being quietly retried until green | mitigate | The plan names in advance which outcomes are legitimate findings to record (`FAIL [P0-ENV]`, `FAIL [P0-TMP]`, any of the four P1-CMD surfaces) and which single outcome justifies a re-run (`FAIL [P1-CMD]: indeterminate`), with a hard cap of three runs and a mandatory escalation.
