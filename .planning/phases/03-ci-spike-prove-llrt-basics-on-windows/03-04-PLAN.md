<objective>
Prove the probe's failure path works, by breaking it on purpose and watching CI go red.

Purpose: Plan 03-03 produced a result. This plan proves that result means something. The chain from "an assertion fails" to "the job is red" runs through `node ... 2>&1 | tee probe-results.txt` under `shell: bash`, and depends on GitHub mapping that to `bash --noprofile --norc -eo pipefail {0}` so `pipefail` returns the probe's exit code instead of `tee`'s. `03-RESEARCH.md` logs this as assumption A2 and Pitfall 1 warns of the exact failure shape: CI shows green while `probe-results.txt` contains `FAIL [P0-ENV]`. Static reasoning does not close it — D-13 says so directly, and `03-PATTERNS.md` excerpt 7 prescribes a deliberate-FAIL run, the same way plan `01-06` run 2 proved the lint gate actually bites rather than trusting the YAML.

Without this plan, a probe that could never fail the job would be indistinguishable from a probe that passed.

Output: no net change to any repository file. One mutation is made, pushed on a throwaway branch, observed, and reverted. The deliverable is the recorded evidence plus a clean remote.
</objective>

  <action>
    Make the smallest possible mutation that forces a P0 failure, push it on its own throwaway branch, and record what CI does.

    MUTATE. In `scripts/windows-llrt-probe.mjs`, change the single P0-TMP platform comparison literal from `"win32"` to `"win32x"`. That is a one-character edit to one line, chosen for four reasons: it forces `FAIL [P0-TMP]`, which is a gating assertion under D-06; it leaves every other assertion running normally so the run still produces all seven lines; it introduces no lint error, so the four `Verify (Node N)` legs stay green and the probe job's red is attributable to the probe alone; and it reverts exactly.

    Do not mutate P0-ENV instead. A forced P0-ENV failure would produce a `FAIL [P0-ENV]` line in a public run record, and D-05 makes that specific line the trigger for a project-stopping blocker — a deliberately fabricated one sitting in the archive is a trap for whoever reads it later.

    PUSH. Create `scratch/ci-proof-windows-probe-negative` from the same base commit as the baseline run. Commit the mutation with a targeted `git add scripts/windows-llrt-probe.mjs` — never `git add -A`, the repository is public. Push only that branch. This commit is meant to be destroyed with its branch and to survive only in the run record, exactly as `01-06`'s two scratch commits were.

    OBSERVE. Wait for the probe run to complete, then record from `gh run view <id> --json jobs`: the job conclusion, which step failed and its step number, and the conclusion of `Upload probe results`.

    Four things must be true, and each closes a distinct hole:
      - The job conclusion is `failure`. This is the empirical closure of assumption A2 and Pitfall 1: the probe's non-zero exit survived `tee`. Had `pipefail` not applied, the job would be green with a `FAIL` line sitting in the artifact.
      - The failing step is `Run LLRT Windows primitive probe`, not an earlier one. If the D-10 gate step or `Setup Node` failed instead, the run proves nothing about the probe's exit path.
      - `Upload probe results` still ran and concluded `success` rather than being skipped. This is the proof of `if: always()`, and it is the only run in the phase that can prove it, because on a green run an unconditional upload and a conditional one are indistinguishable.
      - The uploaded `probe-results.txt` still contains all seven assertion IDs and contains `FAIL [P0-TMP]`. A red run whose artifact only holds a crash trace would mean the probe died rather than reported, and the gate would be untested.

    CROSS-CHECK THE NEGATIVE LEGS. Confirm the `CI` run on this same commit concluded `success` on all four `Verify (Node N)` legs. This is decision `[01-06]`'s rule applied here: an all-red push would discriminate nothing, and this is what proves the probe job's red comes from the probe rather than from anything Phase 3 did to the repository.

    REVERT. Restore the file with `git checkout <baseline-sha> -- scripts/windows-llrt-probe.mjs`, then prove the restoration rather than assume it: `git diff --exit-code` against the baseline must be silent, and `git rev-parse HEAD:scripts/windows-llrt-probe.mjs` on the working branch must equal the hash recorded before the mutation. Confirm `grep -c 'win32x' scripts/windows-llrt-probe.mjs` returns 0.
  </action>
