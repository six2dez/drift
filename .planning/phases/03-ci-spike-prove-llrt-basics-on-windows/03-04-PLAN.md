<objective>
Prove the phase's two verification gates work, by breaking each on purpose and watching CI go red.

Purpose: Plan 03-03 produced a result. This plan proves that result means something, and that the one artefact this phase leaves behind for Phases 4-8 — the D-10 secret gate — is not an unfalsified assertion.

The first chain, from "an assertion fails" to "the job is red", runs through `node ... 2>&1 | tee probe-results.txt` under `shell: bash`, and depends on GitHub mapping that to `bash --noprofile --norc -eo pipefail {0}` so `pipefail` returns the probe's exit code instead of `tee`'s. `03-RESEARCH.md` logs this as assumption A2 and Pitfall 1 warns of the exact failure shape: CI shows green while `probe-results.txt` contains `FAIL [P0-ENV]`. Static reasoning does not close it — D-13 says so directly, and `03-PATTERNS.md` excerpt 7 prescribes a deliberate-FAIL run, the same way plan `01-06` run 2 proved the lint gate actually bites rather than trusting the YAML.

The second chain is the D-10 gate. D-10 keeps that gate specifically so the no-secret-material property stays true while Phases 4-8 edit these files. Everything in this phase is deleted in Phase 9 except that property and the findings document — which makes an unproven gate the weakest link in the evidence chain. The same `[01-06]` discipline applies: a gate that has never been observed to fail is indistinguishable from a gate that cannot fail.

Without this plan, a probe that could never fail the job would be indistinguishable from a probe that passed, and a gate that could never fail would be indistinguishable from a repository that is clean.

Output: no net change to any repository file. Two mutations are made, each pushed on its own throwaway branch, observed, and left behind with its branch. The deliverable is the recorded evidence plus a clean remote.

**Why two runs and not one.** The gate step runs *before* the probe step. Putting both mutations in one commit would fail the job at the gate and skip the probe entirely, destroying the probe-exit-path proof — which requires the failing step to be `Run LLRT Windows primitive probe` specifically. The two defects must therefore be observed on separate commits. Each probe job is short and the second run is worth its runner minute: it is the only run in the phase that can prove both the gate branch and `if-no-files-found: error`.
</objective>
