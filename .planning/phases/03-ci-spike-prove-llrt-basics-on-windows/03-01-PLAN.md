  <action>
Create the directory scripts/ at the repo root and write scripts/windows-llrt-probe.mjs as a pure ES module (.mjs extension — matches the project's mcp-server.mjs convention). The file uses only Node.js built-in modules: import from "child_process", "os", "fs", "path", "url", and "node:crypto". No external npm packages. No build step required.

FILE STRUCTURE — implement all of the following in order:

IMPORTS: Import `spawn` from "child_process"; `tmpdir`, `platform` from "os"; `existsSync`, `writeFileSync`, `unlinkSync` from "fs"; `join` from "path"; and `crypto` (default import) from "node:crypto". The bare "os" import at the top level is itself the P2-OS assertion — if the script starts at all, bare "os" resolved.

RESULT TRACKING: Declare a module-level `results` array. Implement three emitters:
- `pass(id, detail)`: logs `PASS [${id}]: ${detail}` to stdout and pushes `{id, status:"PASS", detail}` to results.
- `fail(id, reason)`: logs `FAIL [${id}]: ${reason}` to stderr and pushes `{id, status:"FAIL", detail:reason}` to results.
- `info(id, detail)`: logs `INFO [${id}]: ${detail}` to stdout only (not tracked in results).

SPAWN HELPER: Implement `spawnCapture(cmd, args, opts={})` returning a Promise resolving to `{stdout, stderr, exitCode, spawnError}`. Inside: wrap `spawn(cmd, args, {...opts, stdio:["ignore","pipe","pipe"]})` in a try/catch — if spawn itself throws synchronously, resolve immediately with `spawnError` set. Accumulate stdout/stderr via `data` events. Resolve on the `close` event. Also attach an `error` event handler that sets `spawnError`. Include a 5-second safety timeout via `setTimeout` that calls `child.kill()` then resolves with `spawnError: new Error("timeout")` — this guards against hung `.cmd` processes.

ASSERTION FUNCTIONS:

P0-ENV (assertP0Env, async, FATAL on fail): Build sentinel as `"drift-probe-sentinel-" + Date.now()`. Call `spawnCapture(process.execPath, ["-e", "process.stdout.write(process.env.SENTINEL||'MISSING')"], {env:{SENTINEL:sentinel}})`. The env option MUST contain only the SENTINEL key — no PATH, no inheritance — because `process.execPath` is an absolute path and the inline script needs no PATH lookup. This proves the env option works in isolation per Pitfall 2 in RESEARCH.md. If `spawnError`: call fail("P0-ENV", ...) with the error code. If `stdout.trim() === sentinel`: call pass("P0-ENV", ...). Otherwise: call fail("P0-ENV", ...) showing what stdout actually contained. The SENTINEL value is a dummy timestamp string — never a real Caido token.

P0-TMP (assertP0Tmp, sync, FATAL on fail): Call `tmpdir()` and `platform()`. Call `info("P0-TMP", ...)` logging both values. Check three conditions: (a) `platform() === "win32"`, (b) `/^[A-Za-z]:[\\\/]/.test(td)`, (c) `existsSync(td)`. If all three pass: call pass("P0-TMP", ...) with both values. If any fail: call fail("P0-TMP", ...) identifying which condition failed first.

P1-CMD (assertP1Cmd, async, NEVER fatal): Compute `cmdPath = join(tmpdir(), "probe-test-" + Date.now() + ".cmd")`. In a try/finally (finally always calls `unlinkSync(cmdPath)` ignoring errors): write `"@echo off\r\necho CMD_PROBE_RAN\r\n"` to cmdPath via `writeFileSync`. Call `spawnCapture(cmdPath, [])` with no env options (default inheritance). Record whatever happens: if `spawnError`, call `pass("P1-CMD", ...)` noting the error code (e.g. EINVAL means Node's CVE-2024-27980 guard triggered — that is the expected behavior on Node ≥ 18.20.2 and means cmd.exe /c branch is mandatory in Phase 7). If stdout includes "CMD_PROBE_RAN", call `pass("P1-CMD", ...)` noting that direct .cmd spawn succeeded (LLRT may not implement the EINVAL guard — cmd.exe /c is still the safer production choice). Any other outcome: call `pass("P1-CMD", ...)` recording what occurred. This assertion is always PASS regardless of outcome — it is purely observational data for Phase 7 planning. See Pitfall 3 in RESEARCH.md regarding AV scan delays causing EPERM/EBUSY — record those as-is.

P1-WHERE (assertP1Where, async, NOT fatal): Use the hardcoded absolute path `"C:\\Windows\\System32\\where.exe"` — do NOT use just "where.exe" because Git Bash on windows-latest may not include System32 in its PATH (Pitfall 4). Call `spawnCapture("C:\\Windows\\System32\\where.exe", ["node"])`. If `spawnError`: call fail("P1-WHERE", ...) with the error. Otherwise split stdout on `/\r?\n/`, trim each line, filter empty strings. If `lines.length === 0`: call fail("P1-WHERE", ...) noting zero output. If `lines.length > 0`: call pass("P1-WHERE", ...) including the first line and whether it ends `.exe` (preferred) or not, and the total line count (shows CRLF splitting worked).

P2-OS (assertP2OsImport, sync): The bare `import { tmpdir, platform } from "os"` at the top of the file already proved the specifier resolves — if execution reached this point, it worked. Call pass("P2-OS", ...) with a note that the bare "os" specifier resolved at module load time, and that per LLRT's resolver source (llrt_modules/src/module/resolver.rs, `name.trim_start_matches("node:")`), "os" and "node:os" are identical in LLRT.

P3-VARS (assertP3EnvVars, sync): Check `process.env.USERPROFILE`, `process.env.APPDATA`, `process.env.LOCALAPPDATA`. For each present variable, emit `info("P3-VARS", "${VAR} = ${value}")`. Collect missing vars. If none missing: call pass("P3-VARS", ...) listing all three. If any missing: call fail("P3-VARS", ...) listing which are absent.

P3-UUID (assertP3Uuid, sync): Check `typeof globalThis.crypto?.randomUUID === "function"` (webCryptoAvailable) and `typeof crypto.randomUUID === "function"` (nodeCryptoAvailable). If either is true: call pass("P3-UUID", ...) noting which surfaces are available. If both false: call fail("P3-UUID", ...) with note that the fallback is a Math.random hex loop.

MAIN FUNCTION (async): Print a header block: the literal string "=== Drift LLRT Windows Primitive Probe ===" followed by the Node version (`process.version`) and platform (`process.platform`), then the vehicle explanation ("Vehicle: Node.js — LLRT standalone binary unavailable on windows-latest" and "LLRT evidence: spawn env uses CreateProcess, same OS mechanism as Node"). Then run assertions in this order: await assertP0Env(), assertP0Tmp(), await assertP1Cmd(), await assertP1Where(), assertP2OsImport(), assertP3EnvVars(), assertP3Uuid(). After all run, print "=== Summary ===" and one line per results entry. Then filter results for P0 failures (id === "P0-ENV" || id === "P0-TMP", status === "FAIL"). If any P0 failures: `console.error("PROBE FAILED: P0 assertions failed — direct-spawn+env architecture needs fallback. See RESEARCH.md fallback: .cmd launcher with set KEY=VALUE calls node.")` then `process.exit(1)`. If no P0 failures: `console.log("PROBE PASSED: P0 assertions green — proceed to Phase 4.")` then `process.exit(0)`.

Wrap with `main().catch(err => { console.error("Unhandled probe error:", err); process.exit(1); })`.

Add a file-level comment block at the top (before imports) explaining: Phase 3 CI Spike; vehicle is Node.js because no LLRT Windows binary exists; all assertions use OS-level facts that hold regardless of runtime; cite the LLRT child_process Rust source for the env option.

SENTINEL SECURITY NOTE: The sentinel value is `"drift-probe-sentinel-" + Date.now()` — a predictable but harmless timestamp string. It is NOT a real Caido token, API key, or secret. It is printed verbatim in CI logs. This is intentional and safe.
